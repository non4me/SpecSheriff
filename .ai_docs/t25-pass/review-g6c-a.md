## Findings

- **R1. DOUBT, for the owner.** The problem is in the words "A node's last approval is the last line for the node's sid that is an approval…".
  - An edit may restore an earlier wording whose approval was never withdrawn. By rule 1.3.3 the node is then approved, and `sheriff approve` appends nothing for it.
  - The node's last approval still records the later wording. So s-txbwsthdqhvyzd2 counts every later commit as changing the rule's approved wording, and refuses it unless that commit also changes the rule's tests. No command clears this.
  - Recommended EN: "A node's last approval is the latest line for the node's sid and the fingerprint of its current wording, where that line is an approval. Otherwise, a node's last approval is the last line for the node's sid that is an approval, whether or not a later line withdraws that approval."
  - RU: «Последнее одобрение узла — самая поздняя строка для sid узла и отпечатка его нынешней формулировки, если эта строка — одобрение. Иначе последнее одобрение узла — последняя строка для sid узла, которая является одобрением, независимо от того, отзывает ли это одобрение более поздняя строка.»
