Как расширения устроены технически

Расширения — часть плагина SpecSheriff, а не отдельные плагины. Они приходят с каждым выпуском плагина и спят, пока ответственный не включит их в проекте. Так сказано в согласованном 1.7.1.

3 · Что делают инструменты при каждом запуске

хук агента, git-хук, команда
  1. читают перечень активных расширений из sheriff.config.json
  2. собирают схему: базовая + схемы активных расширений + расширение схемы проекта
  3. проверяют спецификацию по этой схеме: узел типа из неактивного расширения отвергается
  4. запускают проверки SpecSheriff guidelines и проверки активных расширений
  5. sheriff guide печатает агенту SpecSheriff guidelines, правила активных расширений, собственные guidelines проекта и указатель остальных расширений

4 · Как меняется перечень активных расширений

окно sheriff settings с чекбоксами диалог вопроса в чате, при удалённой работе просьба агенту в чате → sheriff extension enable | disable <имя> → ответственный? ничего не зависит от выключаемого? → запись в sheriff.config.json → коммит

5 · Обновление плагина

  • новый выпуск приносит новое расширение → оно появляется в sheriff settings как доступное, но не активно, пока ответственный его не включит
  • выпуск без расширения, которое проект включил → проверки отклоняют коммит и называют это расширение

Почему в проекте записаны только активные. Какие расширения существуют, определяет установленный выпуск плагина. Если скопировать этот перечень в проект, копия будет отставать от плагина после каждого обновления. Поэтому sheriff settings показывает оба перечня: все расширения выпуска, а активные среди них отмечены. Хранится в проекте только выбор.
