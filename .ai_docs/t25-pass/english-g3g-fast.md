Первый коммит репозитория сравнивается с пустым репозиторием. Файл, который коммит перемещает или переименовывает, сравнивается с файлом по его прежнему пути. Добавленная или удалённая коммитом строка — это строка, которую git показывает как добавленную или удалённую, когда сравнивает две версии файла алгоритмом Myers (алгоритмом git по умолчанию), независимо от настроек git на машине.
- Коммит изменяет символ, тест или файл, связанный целиком, если две его версии различаются (§s-u6mj5yv8ngnz79v). Символ или тест тянется от своей первой строки до последней, включая декораторы. Поэтому изменение во вложенном символе изменяет и каждый символ, который его охватывает.
- Символ или тест в родительском коммите — это тот же символ или тест, что и символ с тем же именем, вложенный в символы с теми же именами, в файле в том виде, в каком его оставляет коммит. Тест, который коммит переименовывает, сохраняя его SpecTag и ничего больше в нём не меняя, тоже остаётся тем же тестом (§s-8xw4mgvpexyvw5q, §s-9j2mmnuuwmx5ksn).
- Пример: коммит удаляет строку `log(id);` внутри функции `close` и больше ничего в ней не меняет. Версия `close` в родительском коммите содержит эту строку, поэтому две версии дают разные синтаксические деревья, и коммит изменяет `close`. Вероятнее всего ошибиться, глядя только на строки, которые коммит добавляет: так пропускается изменение, сделанное удалением строк.

### english-group3-changed-g.md · new:tools-7-2-changed-line
TRANSLATION: Заголовок: «Как сравниваются две версии кода».
- Там, где у инструментов SpecSheriff есть грамматика языка файла, они сравнивают две версии символа или файла, связанного целиком (§s-kgbzk2ph9e6jfb4), либо теста (§s-zrsc6asgmhv8tnc), по их синтаксическим деревьям. Каждую версию они разбирают грамматикой tree-sitter для этого языка. Две версии различаются там, где различаются их деревья, когда из обеих исключено следующее:
- каждый комментарий, кроме первой строки файла, если она начинается с `#!`;
- Синтаксическое дерево хранит вид каждой конструкции кода, то, как конструкции вложены, и текст каждого токена, например идентификатора или литерала. Поэтому переименование идентификатора меняет дерево, как и любая правка внутри строкового литерала. Изменение пробельных символов меняет дерево, только если грамматика делает их частью синтаксиса, например отступ строки в Python или YAML.
- файл, связанный целиком (§s-kgbzk2ph9e6jfb4), имя которого заканчивается на `.yaml` или `.yml`, на `.css`, на `.sql`, на `.sh` или на `.json`, — с грамматикой YAML, CSS, SQL, Bash или JSON соответственно.
- Если по грамматике в любой из версий найдена синтаксическая ошибка, две версии различаются там, где различается их текст.
- Reason: изменение кода заставляет инструменты SpecSheriff снова проверить этот код по его правилам (§s-9j2mmnuuwmx5ksn). Синтаксическое дерево сохраняет всё, что может изменить поведение кода, и отбрасывает пробельные символы, которым язык не придаёт значения. Поэтому сравнение деревьев учитывает ровно те правки, которые могут иметь значение. Где у инструментов SpecSheriff нет грамматики языка файла, сравнение текста учитывает каждую правку, так что ни одно изменение кода не проходит непроверенным.
- Пример: коммит сдвигает ключ `retries` ещё на два пробела вправо в файле YAML, связанном целиком, и ключ оказывается вложенным в ключ выше. Грамматика YAML делает отступ частью синтаксиса, поэтому две версии дают разные деревья, и коммит изменяет файл. Вероятнее всего ошибиться, сравнивая только токены: тогда вложенный ключ проходит как неизменённый.
TWO READINGS:
- "a file bound as a whole (§s-kgbzk2ph9e6jfb4) whose name ends in": под вводной фразой "left out of both" пункт читается как ещё одна вещь, исключаемая из обеих версий. Либо это перечень файлов и грамматик, которыми они разбираются. Контекст за второе, но под данной вводной фразой первое прочтение тоже возможно.
- "each comment, other than the file's first line where it opens with `#!`": "it" — это первая строка (она начинается с `#!`) или файл (он начинается с `#!`). Контекст за первую строку. Кроме того, неясно, считается ли первая строка комментарием, который "other than" исключает из исключаемых.
- "which nests the key under the key above it": "which" — это сдвиг (отступ) или коммит или файл. Контекст за сдвиг.
LANGUAGE:
- "other than the file's first line where it opens with `#!`" → "except the file's first line when that line starts with `#!`" — "comment other than a line" смешивает категории, "it opens with" двусмыслен, "where" вместо "when/if", "opens with" вместо "starts with".
- "Where the grammar finds a syntax error in either version" → "Where parsing either version with the grammar yields a syntax error" — грамматика ничего не "находит"; ошибку сообщает парсер. Смысл сохраняется.
- "give different trees" → "produce different trees" — калька с русского «дают».
- "comparing trees counts exactly the edits that can matter" → "comparing trees counts as changes exactly the edits that can matter" — после "counts" нужно дополнение "as changes".
- "comparing the text counts every edit" → "comparing the text counts every edit as a change" — та же причина.
