# Rule 2.6 "The archive" of the SpecSheriff guidelines, as the owner agreed to it again on 2026-11-21

## Title

The archive

## Text

The archive holds the nodes that have ever been approved and have since been removed from the specification. Such a node is placed there together with the reason for its removal. It may also name, by its sid, the node that replaces it. An archived node has no sid of its own.

A section with no node left in it is deleted outright, regardless of what cites it. So is a node that was never approved.

A node may later be deleted from the archive. A node restored from the archive returns to the specification as a new node, with a new sid.

## Reason

The archive keeps the removed rules that the code may have implemented, so that each can be restored. It also keeps what later work can learn from them. The last wording of such a rule shows which line of reasoning or which approach to its problem proved mistaken. A node that was never approved was never implemented, and a section requires nothing, so in the archive either would only bury the rules that had to be removed.

A node may be deleted from the archive at any time, so anything relying on an archived node could break. For that reason, an archived node has no sid by which anything could name it. A sid kept in the archive could also come back into the specification in a copy of its node, and would then name two nodes. The sid of a replacement shows a reader which node replaced the rule at the time of its removal.
