### english-group8d.md · new:tools-15-spec-init — The skill `spec-init`
TRANSLATION:
Новый узел спецификации, выделенный из `s-zh2vcr3xjumppg5`, с sid s-ttsc8tpnu46q53s.

**Заголовок:** Skill `spec-init`

**Текст:** `spec-init` запускает `sheriff init` (§s-7unxytshhc4md54), в плагине для Codex CLI — с опцией `--agent codex` (§s-2pdy9gw2jrjvfb4).

Затем `spec-init` спрашивает у пользователя каждое из следующего, чего нет в `sheriff.config.json` (§s-7unxytshhc4md54), и записывает каждый ответ туда:
- glob-шаблоны, которым соответствуют файлы с кодом системы (§s-hheus6f395ynqvc);
- glob-шаблоны, которым соответствуют файлы с её тестами;
- команду, запускающую тесты (§s-b6qdtghnyha3fhk).

Затем `spec-init` переходит к настройкам runner, который запустила бы `sheriff review` (§s-xr5xxa9cxf2mq5u). Если в git-конфигурации пользователя не записано, что пользователя уже спрашивали о настройках этого runner (§s-p29yawkkkgk7kxb), `spec-init` делает следующее для каждой из этих настроек, которой нет в git-конфигурации пользователя:
- предлагает пользователю значение настройки по умолчанию, чтобы тот подтвердил или заменил его;
- записывает ответ пользователя командой `git config --global`.

Затем `spec-init` записывает, что пользователя спросили о настройках этого runner, как это делает хук, запускаемый при старте сессии (§s-p29yawkkkgk7kxb).

**Обоснование:** Пользователь решает, где проект хранит код и тесты, какая команда запускает тесты и с какими настройками работает ревьюер. Сессия, в которой `spec-init` настраивает проект, началась до того, как в проекте появился `sheriff.config.json`, поэтому хук, запускаемый при старте сессии, не спросил в этой сессии ни одной настройки runner ревьюера (§s-p29yawkkkgk7kxb). За первый запуск ревьюера платит пользователь, поэтому `spec-init` спрашивает до этого запуска.

**Пример:** Пользователь отвечает, что код лежит в `src/`, тесты в `test/`, а запускает их `npm test`. `spec-init` записывает `src/**` и `test/**` как glob-шаблоны и `npm test` как команду. Самая вероятная ошибка — записать `src` и `test`, которым не соответствует ни один файл внутри этих папок.

TWO READINGS:
- "with the option `--agent codex` in the plugin for Codex CLI": (а) опция добавляется, когда skill работает из плагина для Codex CLI; (б) опция «находится в плагине». Контекст — (а).
- "`spec-init` then records that the user has been asked": (а) записывает всегда, даже если уже было записано или ни одной настройки не недоставало; (б) только если спрашивал. "then" после условного абзаца допускает оба; вероятнее (а).
- "`spec-init` then records that the user has been asked about that runner's settings": "that runner" отсылает к runner из предыдущего абзаца ("the runner that `sheriff review` would run").
- "the files holding its tests": "its" — системы (названа в предыдущем пункте списка).
- "each of the following that `sheriff.config.json` lacks": (а) спрашивает только то, чего в конфигурации нет; (б) перечисленного в конфигурации нет вообще. Контекст — (а).
- "The user pays for the reviewer's first run": (а) платит именно пользователь (акцент на «кто»); (б) платит уже за первый запуск (акцент на «когда»). Вывод "asks before that run" требует обоих.
