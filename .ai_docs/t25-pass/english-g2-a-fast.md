### part-a.md · new:tools-9-no-change-trailer
TRANSLATION: **Как сообщение коммита утверждает, что реализация правила не требует изменений.** Сообщение коммита утверждает, что реализация правила не требует изменений, с помощью trailer'а `Implementation-Needs-No-Change: <sid>`, где `<sid>` это sid этого правила. Сообщение содержит по одному такому trailer'у на каждое такое правило. Инструменты SpecSheriff читают trailer'ы сообщения так, как их читает `git interpret-trailers --parse`. Trailer с этим ключом они считают таким утверждением, только если его значение это один sid. **Причина:** trailer это форма, которую git сам даёт для утверждения о коммите, поэтому git и другие инструменты читают его, не разбирая прозу сообщения. **Пример:** коммит меняет текст approved-правила только ради исправления опечатки. Сообщение заканчивается строкой `Implementation-Needs-No-Change: s-…`, называющей правило. Вероятная ошибка: записать утверждение прозой сообщения, например «код не требует изменений для s-…»; инструменты SpecSheriff такую запись не читают.
TWO READINGS:
- "that key": ключ `Implementation-Needs-No-Change` (вероятнее). Слово "key" в тексте не вводилось, только имя trailer'а.
- "which the SpecSheriff tools do not read": "which" это проза сообщения (вероятно) или само утверждение.

- "by the trailer" → "with the trailer" — "states ... by the trailer" это калька с творительного падежа.

- "gives a statement about a commit" → "provides for a statement about a commit" — "gives a statement" читается как "даёт утверждение"; смысл "предусматривает форму для".
