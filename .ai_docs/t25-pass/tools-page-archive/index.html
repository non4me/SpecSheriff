Удалённый узел и архив · A removed node and the archive

tools 7.1.6 · s-j4webte36gkraju · предложение от 2026-11-21 · ждёт вашего согласия
Обоснование
Архив хранит каждое удалённое правило, которое код мог реализовать, и ничего больше (§2.6). У архивного узла нет sid, поэтому запись удалённого узла можно проверить только в коммите, который удаляет узел.
Reason
The archive keeps each removed rule that the code may have implemented, and nothing else (§2.6). An archived node has no sid, so the entry of a removed node can be checked only in the commit that removes the node.

Новое: у узла не было обоснования. Оно говорит, зачем архив и почему запись проверяется только в коммите удаления.

Пример
Коммит удаляет одобренное правило base/3.2 и пустой раздел base/5. Он добавляет в specs/_archive/base.json узел типа TextRule с расположением base/3.2 и формулировкой правила; его поле archived указывает дату и причину. Ближайшая ошибка — отправить в архив и пустой раздел: тогда sheriff validate отвергает коммит и называет specs/_archive/base.json и base/5.
Example
A commit removes the approved rule base/3.2 and the empty section base/5. It adds to specs/_archive/base.json a TextRule that has the location base/3.2 and the rule's wording, and whose archived field gives the date and the reason. The closest mistake is to archive the empty section as well: sheriff validate then refuses the commit, naming specs/_archive/base.json and base/5.

Что убрано из узла

  • «ищет в одобрениях каждый sid»: у узла в архиве sid нет, поэтому одобрения ищутся по sid удалённого узла, прочитанного из коммита до удаления.
  • Проверка файла архива по его схеме перешла в новый узел «Validation of a file of the archive», который идёт сразу после этого.
  • Передача замены дальше: по вашему решению от 21 ноября архивный узел только может назвать замену, и никто её не обновляет.

Одобренная формулировка

Пока вы не согласились с предложением, текстом узла остаётся одобренная формулировка.

Текущий текст узла по-русски
`sheriff validate` ищет в одобрениях каждый sid, который коммит удаляет из спецификации.

- Узел, которому когда-либо давалось одобрение, ищется в архиве вместе с причиной удаления, если это не раздел и не заголовок домена.
- Любой другой узел отвергается, если он стоит в архиве.

Обоснования у узла нет.
Текущий текст узла (English)
`sheriff validate` looks up in the approvals each sid a commit removes from the specification.

- A node an approval was ever given for is looked up in the archive, with the reason for its removal, unless it is a section or a domain's header.
- Any other node is refused where it stands in the archive.
