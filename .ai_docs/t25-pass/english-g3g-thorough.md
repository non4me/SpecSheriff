- Причина: изменение кода заставляет инструменты SpecSheriff снова проверить этот код по его правилам (§s-9j2mmnuuwmx5ksn). Синтаксическое дерево сохраняет всё, что может изменить поведение кода, и отбрасывает пробельные символы, которым язык не придаёт значения. Поэтому сравнение деревьев учитывает ровно те правки, которые могут иметь значение. Если у инструментов SpecSheriff нет грамматики языка файла, сравнение текста учитывает каждую правку, чтобы ни одно изменение кода не прошло без проверки.
- Пример: коммит сдвигает ключ `retries` ещё на два пробела в YAML-файле, связанном целиком, и этим вкладывает ключ в ключ над ним. Грамматика YAML делает отступ частью синтаксиса, поэтому две версии дают разные деревья, и коммит изменяет файл. Самая вероятная ошибка — сравнивать только токены: тогда вложенный ключ сойдёт за неизменённый.
