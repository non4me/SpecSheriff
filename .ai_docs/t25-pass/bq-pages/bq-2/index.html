Title

Setting a repository up and taking SpecSheriff out of it

Text

One procedure of the SpecSheriff tools sets a repository up for those tools, and another takes SpecSheriff out of it. Taking SpecSheriff out removes what setting the repository up wrote outside the specification. It also removes the settings of the SpecSheriff tools that the repository's configuration holds, including the entries that set the specification's approval status (§s-qzthyh7yqvfhsa2), its strict flag (§s-q3pfzyaxvpr2zj2) and the extensions that the project has chosen (§s-9ttvcwpqkehm58g). It leaves the specification, the bindings file (§s-kgbzk2ph9e6jfb4), the system's code (§s-hheus6f395ynqvc), and the repository's own tools and their tests as they are.

Reason

A project can take up SpecSheriff or stop using it without knowing which files and settings the SpecSheriff tools need, and keeps its specification, which states what its system does, either way.

Title

A rule may be a table

Text

A rule may be set out as a table, as a node of the kind TableRule. A TableRule has a title, a text and a reason, as a TextRule has. It also names its table's columns. Each cell of the table holds either text or a node of a kind that the specification's schema declares and whose nodes need no title, such as a rule. A node in a cell has no title of its own. Its column and its row name it. The rows may be grouped under headings.

Reason

A table shows at a glance what many requirements share and where they differ. A requirement that is a node in a cell can be approved, cited and bound to code on its own.

Варианты RecordType изменённый узел
s-z3dnru6qqdf9m6j · extensions/recordtype/12.6
Title

RecordType variants

Text

A RecordType variant adds the fields that a data record of a RecordType (§s-7vm323mhry2enx3) holds because of the values of some fields of that RecordType. The fields of the RecordType whose values decide this are the fields that select a RecordType variant. They are named by the RecordType itself or by a RecordType that it refines. Each combination of their values, one value for each field, has its own RecordType variant if the combination adds fields of its own, and only then.

A RecordType variant is a RecordType that:

  • is declared where the RecordType that it is a variant of is declared: in the same section of the base specification or in the contracts section (§s-z6tq6a3btnvvwx7);
  • has a refines link (§s-sn6au3vcr9uy5pm) to that RecordType;
  • names the values it corresponds to, one value for each field that selects a RecordType variant.

A RecordType variant adds the fields that it declares. It also adds each field that it takes through refines from another RecordType, unless its RecordType is that RecordType or reaches it through refines. A data record holds the fields of its RecordType variant alongside the fields of its RecordType. The name of each field that a RecordType variant adds differs from the name of every field that its RecordType declares or takes through refines from another RecordType.

Reason

Where the values of some fields decide which other fields a data record holds, a RecordType alone does not describe every field that the parts of the system that read its data records can expect. Its RecordType variants describe the rest. Since they are declared where the RecordType is declared, those parts of the system find the whole description of the data records where they look for the RecordType (§s-7vm323mhry2enx3).

Examples

The RecordType of a notification names its field channel as the field that selects its RecordType variant. The value email adds the field address, so the RecordType variant for email declares address. A data record of an email notification holds address alongside channel and text. The value app adds no field, so it has no RecordType variant.

In a base specification divided into domains, the audit domain declares the RecordType of an audit log entry, whose field domain takes the names of the domains as its values. Entries about orders also hold the order number. The value orders comes from the orders domain, but its RecordType variant is declared in the audit domain.

Заголовок

Варианты RecordType

Текст

Вариант RecordType добавляет поля, которые запись данных RecordType (§s-7vm323mhry2enx3) содержит из-за значений некоторых полей этого RecordType. Эти поля — поля, которые выбирают вариант RecordType. Их называет сам RecordType или RecordType, который он уточняет. Каждое сочетание их значений, по одному значению каждого поля, имеет свой вариант RecordType, если это сочетание приносит собственные поля, и только тогда.

Вариант RecordType — это RecordType, который:

  • объявлен там же, где RecordType, вариантом которого он является: в том же разделе базовой спецификации или в контрактах (§s-z6tq6a3btnvvwx7);
  • ссылается через связь refines (§s-sn6au3vcr9uy5pm) на этот RecordType;
  • называет значения, которым он соответствует, по одному значению каждого поля, которое выбирает вариант.

Вариант RecordType добавляет поля, которые он объявляет. Он добавляет и каждое поле, которое получает через refines от другого RecordType, если только его RecordType не является этим RecordType и не достигает его через refines. Запись данных содержит поля своего варианта RecordType рядом с полями своего RecordType. Имя каждого поля, которое добавляет вариант RecordType, отличается от имени каждого поля, которое его RecordType объявляет или получает через refines от другого RecordType.

Обоснование

Когда значения одних полей определяют, какие ещё поля содержит запись данных, сам RecordType описывает не все поля, которых могут ожидать части системы, читающие его записи данных. Остальное описывают его варианты RecordType. Поскольку варианты объявлены там же, где RecordType, эти части системы находят полное описание записей данных там, где ищут сам RecordType (§s-7vm323mhry2enx3).

Примеры

RecordType уведомления называет своё поле channel полем, которое выбирает его вариант. Значение email приносит поле address, поэтому вариант RecordType для email объявляет address. Запись данных уведомления по email содержит address рядом с channel и text. Значение app не приносит полей, поэтому варианта RecordType у него нет.

В базовой спецификации, разделённой на домены, домен аудита объявляет RecordType записи журнала аудита. Значения его поля domain — имена доменов. Записи о заказах содержат ещё номер заказа. Значение orders приходит из домена заказов, а его вариант RecordType объявлен в домене аудита.

Согласованная формулировка, которую узел заменяет
Title

RecordType variants

Text

A RecordType variant declares the fields that a data record of a RecordType (§s-7vm323mhry2enx3) holds because of the values of some fields of that RecordType. The fields of the RecordType whose values decide this are the fields that select a RecordType variant. They are named by the RecordType itself or by a RecordType that it refines. Each combination of their values, one value for each field, has its own RecordType variant if the combination adds fields of its own, and only then.

A RecordType variant is a RecordType that:

  • is declared where the RecordType that it is a variant of is declared: in the same section of the base specification or in the contracts section (§s-z6tq6a3btnvvwx7);
  • has a refines link (§s-sn6au3vcr9uy5pm) to that RecordType;
  • names the values it corresponds to, one value for each field that selects a RecordType variant.

A data record holds the fields of its RecordType variant alongside the fields of its RecordType. The name of each field that a RecordType variant declares differs from the name of every field that its RecordType declares or takes through refines from another RecordType.

Reason

Where the values of some fields decide which other fields a data record holds, a RecordType alone does not describe every field that the parts of the system that read its data records can expect. Its RecordType variants describe the rest. Since they are declared where the RecordType is declared, those parts of the system find the whole description of the data records where they look for the RecordType (§s-7vm323mhry2enx3).

Examples

The RecordType of a notification names its field channel as the field that selects its RecordType variant. The value email adds the field address, so the RecordType variant for email declares address. A data record of an email notification holds address alongside channel and text. The value app adds no field, so it has no RecordType variant.

In a base specification divided into domains, the audit domain declares the RecordType of an audit log entry, whose field domain takes the names of the domains as its values. Entries about orders also hold the order number. The value orders comes from the orders domain, but its RecordType variant is declared in the audit domain.

Заголовок

Варианты RecordType

Текст

Вариант RecordType объявляет поля, которые запись данных RecordType (§s-7vm323mhry2enx3) содержит из-за значений некоторых полей этого RecordType. Эти поля — поля, которые выбирают вариант RecordType. Их называет сам RecordType или RecordType, который он уточняет. Каждое сочетание их значений, по одному значению каждого поля, имеет свой вариант RecordType, если это сочетание приносит собственные поля, и только тогда.

Вариант RecordType — это RecordType, который:

  • объявлен там же, где RecordType, вариантом которого он является: в том же разделе базовой спецификации или в контрактах (§s-z6tq6a3btnvvwx7);
  • ссылается через связь refines (§s-sn6au3vcr9uy5pm) на этот RecordType;
  • называет значения, которым он соответствует, по одному значению каждого поля, которое выбирает вариант.

Запись данных содержит поля своего варианта рядом с полями своего RecordType. Имя каждого поля, которое объявляет вариант RecordType, отличается от имени любого поля, которое его RecordType объявляет сам или берёт из RecordType, который он уточняет.

Обоснование

Когда значения одних полей определяют, какие ещё поля содержит запись данных, сам RecordType описывает не все поля, которых могут ожидать части системы, читающие его записи данных. Остальное описывают его варианты RecordType. Поскольку варианты объявлены там же, где RecordType, эти части системы находят полное описание записей данных там, где ищут сам RecordType (§s-7vm323mhry2enx3).

3.6. Две строки: additionalProperties и unevaluatedProperties на верхнем уровне
Вариант не пишет на верхнем уровне ни того, ни другого; RecordType с вариантами не пишет additionalProperties.

Определение варианта подключается через then из определения его RecordType. Там additionalProperties или unevaluatedProperties на верхнем уровне schema варианта отвергает поля его RecordType, и каждая запись данных варианта отвергается. Страница о RecordType и JSON Schema, которую вы приняли 2026-11-19, установила, что вариант не пишет unevaluatedProperties. Молча выбрасывать такое слово в sheriff types значило бы молча терять данные.

Обратный случай даёт тот же дефект. По JSON Schema 2020-12 (Core, 10.3.2.3) additionalProperties видит только properties и patternProperties своего объекта, поэтому на верхнем уровне определения RecordType с вариантами отвергает каждое поле, которое добавляет вариант. На той же странице для этого служит unevaluatedProperties: false. Каждая строка говорит одну мысль, поэтому строки остаются отдельными.

Ваши правила «What can run as a deterministic process is automated» и «A release carries out every rule it contains» не оставляют другого выбора, кроме как добавить строку.
